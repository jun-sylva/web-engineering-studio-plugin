# Sources officielles et versions

## Hiérarchie

1. Contraintes du projet et versions verrouillées.
2. Documentation officielle de la version installée.
3. Notes de version, avis de dépréciation et guides de migration officiels.
4. Compilateur, analyseur, linter et tests configurés dans le projet.
5. Spécification du langage ou de la plateforme.

Les blogs, réponses communautaires et extraits de moteur de recherche peuvent aider à trouver une piste, mais ne constituent pas l’autorité finale.

## Procédure

- Lire manifestes et lockfiles ; distinguer version déclarée et version résolue.
- Chercher dans la documentation officielle avec la version dans la requête.
- Vérifier date, statut stable/expérimental, plateforme et éventuelle breaking change.
- Citer URL, version et date de consultation dans le rapport lorsque la recommandation en dépend.
- Séparer : correction compatible actuelle, modernisation facultative et migration majeure.
- Ne jamais remplacer automatiquement une dépendance seulement parce qu’une version plus récente existe.

Si l’accès Internet est indisponible, utiliser les types, sources, changelogs ou docs locales et signaler ce qui reste à vérifier.
