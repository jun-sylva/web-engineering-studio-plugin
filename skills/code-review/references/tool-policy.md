# Politique outils, MCP et sous-agents

L’intention explicite de l’utilisateur prime. Découvrir les outils disponibles avant de proposer une installation. Préférer les analyseurs, tests et scripts déjà configurés dans le projet.

Un MCP n’élargit pas les permissions. Lire n’autorise pas à écrire ; une session authentifiée n’autorise pas une action externe. Ne jamais transmettre code privé, secrets ou données sans accord.

Les sous-agents peuvent analyser en parallèle des zones indépendantes en lecture seule. Le responsable principal fusionne, élimine les doublons, vérifie chaque preuve et reste seul interlocuteur du client. Ne jamais laisser plusieurs agents corriger les mêmes fichiers simultanément.

Toute installation, mise à jour majeure, écriture externe, publication ou déploiement nécessite une autorisation distincte.
