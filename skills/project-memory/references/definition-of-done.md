# Definition of Done orchestrée

Le produit n'est pas déclaré fini tant que les exigences hautes ne relient pas changement, test et preuve, et que les éléments applicables suivants ne sont pas satisfaits ou explicitement acceptés :

- comportement produit et vision ;
- code, contrats, migrations et documentation ;
- revues code et sécurité selon le risque ;
- tests statiques, unitaires, intégration, fonctionnels et non-régression ;
- accessibilité, performance, compatibilité et résilience applicables ;
- observabilité, support et exploitation ;
- artefact/release identifiables ;
- revert du changement et rollback de release vérifiables ;
- risques résiduels avec propriétaire ;
- validation utilisateur finale `VAL-*`.

`qa-engineering` produit le verdict qualité. `release-engineering` produit le verdict de préparation/livraison. `project-memory` ne transforme jamais leur absence en succès.
