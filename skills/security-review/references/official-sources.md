# Standards et sources officiels

Utiliser d'abord la version réellement applicable au projet et citer identifiant/version/date de consultation.

- OWASP Top 10:2025 : https://top10.owasp.org/2025/
- OWASP ASVS 5.0.0 : https://owasp.org/projects/asvs — citer les exigences sous la forme versionnée `v5.0.0-x.y.z`.
- CWE Top 25 2025 : https://cwe.mitre.org/top25/archive/2025/2025_cwe_top25.html
- OWASP Secure Code Review Cheat Sheet : https://cheatsheetseries.owasp.org/cheatsheets/Secure_Code_Review_Cheat_Sheet.html
- OWASP Web Security Testing Guide : https://owasp.org/projects/web-security-testing-guide — distinguer la stable 4.2 du contenu v5 en développement.
- NIST Secure Software Development Framework 1.1 : https://www.nist.gov/publications/secure-software-development-framework-ssdf-version-11-recommendations-mitigating-risk

Ajouter les avis officiels du langage, framework, fournisseur cloud ou dépendance concernés. Distinguer standard stable, brouillon, recommandation et exigence réglementaire. Une correspondance OWASP/CWE aide la communication mais ne prouve pas le constat.
